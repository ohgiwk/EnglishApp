# アプリの学習機能と設計

単語学習・音声・昇級試験・保存処理を修正する際の責務と、維持すべき動作をまとめる。語彙追加の作業手順は [語彙設計](vocabulary-design.md)、データ構造は [データREADME](../src/data/vocabulary/README.md) を参照する。通常の語彙拡充では本資料を毎回読む必要はない。

## 1. 実装の責務

画面は表示と操作の入り口、composableは学習中の状態と音声制御、domainは出題・採点などの規則を担当する。保存状態はappストアが所有し、永続化処理をpersistenceに分離する。以下のパスは `src/` を基準とする。

| 領域       | 主な実装                                                                | 責務                                                                  |
| ---------- | ----------------------------------------------------------------------- | --------------------------------------------------------------------- |
| 学習画面   | `views/VocabularySessionView.vue`、`components/vocabulary/`             | 画面配置、ルート移動、出題形式ごとの入力、結果・中断確認              |
| 回答処理   | `composables/useVocabularyExercise.ts`                                  | 回答中・カード確認中・結果表示中・記録中の状態と採点                  |
| 出題表示   | `domain/vocabulary-presentation.ts`                                     | 問題文、答え、例文、日本語訳、読み上げ対象                            |
| 音声制御   | `composables/useVocabularySpeech.ts`、`composables/useEnglishSpeech.ts` | 問題変更・回答・ミュート・手動再生の制御、画面破棄時の音声停止        |
| 音声基盤   | `speech.ts`、`voice-catalog.ts`                                         | ブラウザ音声API、遅延再生・キャンセル、音声候補の選別・重複除去・分類 |
| ダイアログ | `components/BaseDialog.vue`                                             | フォーカス移動・復帰、背景のinert化、Escape、スクロール制御           |
| 状態更新   | `stores/actions/`                                                       | 会話・単語練習・旧会話互換の操作                                      |
| 集計・報酬 | `domain/study-statistics.ts`、`domain/study-rewards.ts`                 | 学習集計と報酬の計算                                                  |
| 昇級試験   | `domain/promotion-exam.ts`、`stores/actions/promotion-exam.ts`          | 受験資格・出題・正解の決定、試験セッションと合否の管理                |
| 永続化     | `persistence/`                                                          | 保存形式の検証、旧形式からの移行、ストレージ操作                      |

## 2. 通常学習の動作

### 回答と記録

答え合わせで結果を表示し、「次の問題へ」で回答を記録する。フラッシュカードは自己評価時に記録する。操作の重複によって報酬を二重に付与しない。

### 読み上げ

穴埋め・並べ替えは出題時に読み上げず、正誤にかかわらず回答時に完成英文を読む。ミュートは自動再生にだけ適用し、結果ダイアログの手動再生は可能とする。画面を破棄した際は音声を停止する。

### 例文による出題制限

`exampleInfo` は例文の由来・確認状態・使用可能な出題形式を管理する。未確認の生成例文は穴埋め・並べ替えに採用せず、選択した単語を除外する代わりに英→日へ切り替える。学習開始画面にもこの条件を表示する。

`authored` という値だけで文法や教材品質の確認が完了したと判断しない。`hasUsableBilingualStructure` も構造の検査であり、内容の品質判定ではない。意味・品詞・英和例文の個別確認と登録方法は [データREADME](../src/data/vocabulary/README.md) に従う。アプリとNodeの検証ツールは同じ分割データを読む。

## 3. 昇級試験の動作

| 項目             | 動作                                                                            |
| ---------------- | ------------------------------------------------------------------------------- |
| 受験資格         | 対象レベルが20語以上あり、70%以上を習得済みであること。獲得した資格を永続化する |
| 出題と合格       | 20問中18問以上の正解で次レベルを解放する                                        |
| 受験順           | 各レベルを順番に受け、最終レベルには試験を設けない                              |
| 試験中           | 音声と正解を表示しない                                                          |
| 結果画面         | 全回答の確認と手動発音ができる                                                  |
| 通常学習との関係 | 通常練習の報酬・実績を更新しない                                                |
| 中断・再読み込み | メモリ上の試験セッションを破棄する                                              |

新しい受験資格は練習結果に記録する。通知済み状態を保持し、同じ案内ダイアログが繰り返し表示されることを防ぐ。

## 4. 保存と旧データの移行

保存形式はv7とし、旧会話の保存データとの互換性を維持する。試験中の一時セッションと、受験資格・合格状態などの永続データを区別する。

| 読み込む保存形式 | レベル解放と履歴の扱い                              |
| ---------------- | --------------------------------------------------- |
| v6以前           | 学習履歴を保持したまま、レベル1からの解放状態へ戻す |
| v7以降           | 連続した合格済みレベルから解放レベルを復元する      |

試験結果の履歴は30件まで保持する。合格状態はこの件数上限とは独立して保持し、古い結果が履歴から外れても失われないようにする。

## 5. 変更時の検証

| 検証                       | 対象                                                                       |
| -------------------------- | -------------------------------------------------------------------------- |
| `npm run vocabulary:check` | 語彙ファイルのID範囲、重複、例文の確認状態と出題条件                       |
| `npm run check`            | 上記データ検証、Lint、書式、データ・保存・画面・音声・ダイアログ等のテスト |
| `npm run build`            | TypeScriptと本番ビルド                                                     |

語彙・コード変更ではcheckとbuildを実行する。checkに含まれるデータ検証を別途重複実行する必要はない。PRとデプロイ前のCIでも検証する。書式チェックはiOSへコピーされたWeb成果物や画像カタログなどの生成物を除外する。

音声の回帰テストはAPI呼び出しを検証する。端末固有の声質や実際の音量は実機で確認する。文書のみの変更は整形・リンク・データ不変を確認し、アプリの全テストやビルドは繰り返さない。作業量と検証の運用は [AGENTS.md](../AGENTS.md) に従う。
