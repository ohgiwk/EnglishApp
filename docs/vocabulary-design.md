## 編集基準（editorial-policy-v1）

- 基本義の学習段階、読解上の重要性、抽象度、題材のバランスで分類。Web頻度は補助情報。CEFR・英検・学年との厳密対応は示さない。
- 基礎の欠落、高校・標準入試、発展読解の順に検討。活用形・綴り違いで水増ししない。派生語は独立の学習価値で判断。熟語数は別にする。
- `reviewed` はアプリ内の個別編集確認であり、外部認証や入試頻度の実測ではない。意味・品詞・英和例文を読み合わせる。自動テストで語義の正しさを保証しない。
- `legacy-frequency-order` は旧版の選択順による分類で、これだけを根拠に確認済みにしない。辞書参照IDとURLの過去記録は[履歴](vocabulary/archive/vocabulary-audit-history.md)内をID検索する。

## データ・検証の不変条件

- 固定IDの100語ごとのJSONに意味・例文・別義・注記・編集情報をまとめる。[編集場所](../src/data/vocabulary/README.md)。並び順からIDやレベルを再生成しない。
- 既存IDと見出しの対応を保持し、レベル変更で学習履歴を失わせない。新規語には未使用IDを割り当てる。大小文字の修正はIDを維持する。
- `level` と `editorial.recommendedLevel` を一致させ、理由・参照元・確認状態を記録する。
- 重要な別義は `additionalMeanings` に品詞・英和例文付きで保存。基本義でレベル判定し、別義は表示用。四択の正解は基本義。
- 確認した独自例文は `authored`。未確認の生成例文は `generated` / `needs-review` とし、穴埋め・並べ替えに使わない。
- ID・見出し重複、例文と出題許可、学習履歴、実数表示、各レベルの出題を検証。`npm run check` と `npm run build` をデータ変更後に実行する。
- 収録数が指定問数未満なら実数まで出題。四択候補は同レベル優先、不足時は下位から補い、上位の未解放語を混ぜない。20語未満の昇級試験は開始を防ぎ、取得済み資格・履歴は保持する。

## 公開問題との照合

対象年度・大学・問題・ページ範囲・抽出方法を明記。原形統合や文脈語義の確認と、単純表記一致を区別する。単一題の率は理解率や合格率ではない。

`scripts/vocabulary-coverage.mjs <text> <year> <question> <https-url> [extraction-description]` で集計する。NFKC・小文字化、内部アポストロフィを含む英字単位、ハイフン分割、`/cNNN`除去。数字は数えず、原形統合・固有名詞除外はしない。手動転記では第5引数で範囲を必ず明示する。

- 共通テスト2025: 公開PDF全32ページの抽出可能な英語。本文・設問・選択肢・図中文字を含む。最新集計 [集計JSON](vocabulary/exams/vocabulary-coverage-2025.json)、初回1,050語は別JSONで保持。
- [九州2025](vocabulary/exams/vocabulary-audit-kyushu-2025.md): 著作権による本文欠落があり、本文網羅率とは扱えない。
- [慶應2025第1問](vocabulary/exams/vocabulary-audit-keio-2025-q1.md)・[第2問](vocabulary/exams/vocabulary-audit-keio-2025-q2.md): 本文照合済み。ただし同大学・同年度のみ。各JSONは当時の語数のスナップショット。

入力テキストとカタログのハッシュを残す。公式問題の全文や画像はリポジトリに転載しない。必要時に該当レポートの再現条件を確認する。
