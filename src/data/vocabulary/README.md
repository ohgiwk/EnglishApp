## 一緒に編集する情報

各レコードは以下を含みます。意味と例文を別のファイルに登録する必要はありません。

- `id`, `word`: 固定IDと見出し語。
- `meaningJa`, `partOfSpeech`, `category`, `level`: 基本義、品詞、分類、レベル。
- `example`, `exampleJa`: 基本義に対応する英語例文と和訳。
- `additionalMeanings`: 必要な別義。各別義の品詞・意味・英語例文・和訳を一緒に記述。
- `usageNote`: 必要な場合のみ、学習者に表示する用法や綴りの注意。
- `editorial`: レベル判定理由・参照元・確認状態。`recommendedLevel` と `level` を一致させる。
- `exampleInfo`: 例文の由来・確認状態・許可する出題形式。

レベル・語義の確認状態と例文の確認状態は別です。現在は全語が編集確認済みです。移行時の `curated` / `core` は由来を保存するための値です。新しく確認した独自例文は `authored`、未確認の生成例文は `generated` / `needs-review` とします。後者で許可する出題は `en-to-ja`, `ja-to-en`, `flashcard` のみです。

例文が保存されていても文法や訳が正しいと自動的に認定されるわけではありません。基本義・品詞・例文の使い方を読み合わせてから確認済みにしてください。

## 追加と検証

1. 次の未使用IDを割り当て、そのIDを含む100語範囲のファイルへ追加します。現在は5,034語です。追加が必要な場合の次の未使用IDは `v5035` です。規模目標到達後は入試本文の照合と不足確認を優先します。
2. 新しい100語範囲に入ったら `v1101-v1200.json` のようなファイルを作ります。単語を並べ替えてIDを振り直さないでください。
3. `npm run vocabulary:check` でファイルのID範囲、重複、必須情報、例文と出題条件を確認します。
4. `npm run check` と `npm run build` を実行します。

アプリ側の `../vocabulary-catalog.ts` はファイルを自動収集しID順で読み込みます。Nodeの検証・入試照合も同じディレクトリを読むため、追加時に個別のimportを増やす必要はありません。誤ったファイル名やID範囲は検証エラーになります。

レベル名・収録目標は `../vocabulary.ts` にあります。現在の収録数は単語データから算出されます。監査の進捗と教育上の基準は [語彙設計](../../../docs/vocabulary-design.md) を参照してください。
